## 为什么需要 ToDO？—— 核心差异化定位

在当今的办公协同工具中，团队往往面临两极分化的尴尬选择：

- **走向一极：个人待办清单工具（如 Microsoft To Do）**：
  它们在单兵作战时轻巧趁手，但**几乎没有真正的团队属性**——无法建立组织空间、无法进行多级 WBS 目标拆解派工、没有单责任人制约束、无法跨部门群提醒催办、缺乏权限隔离与离队交接治理。团队一旦协作起来，信息瞬间支离破碎。
- **走向另一极：传统重型协同系统（如 Teambition、Jira）**：
  它们功能厚重庞杂，却伴随着复杂的配置、漫长的工作流审批、大量的生硬表单与高昂的学习成本。员工每天上班花在“填表应付、排期对齐”上的精力甚至超过了干活本身，不仅反人性，而且私有化部署笨重、授权成本高昂。

### ToDO 的甜蜜平衡点：轻量、高效，覆盖真实工作全流程

**ToDO 任务管理器**既不做孤岛式的个人备忘录，也不做枷锁式的重型敏捷系统。我们巧妙融合了**「个人任务的清爽随手办」**与**「团队任务的严密权责闭环」**：

| 考量维度 | 个人待办工具（如 Microsoft To Do） | 传统重型协作工具（如 Teambition / Jira） | **ToDO 任务管理器（本系统）** |
| :--- | :--- | :--- | :--- |
| **产品属性** | 偏个人备忘，单兵好用但缺乏团队基因 | 偏工程敏捷看板，流程重、表单多、侵入感强 | **轻量团队中枢 + 个人 4 维清爽执行** |
| **协同负荷** | 仅支持简单清单共享，无空间与权限治理 | 配置复杂，字段繁琐，全员学习与维护成本高 | **零学习成本，开箱即用，无繁文缛节与表单负担** |
| **权责机制** | 缺乏主责人定义，多人协作职责不清 | 流程僵硬，容易流于形式与推诿扯皮 | **坚守单人负责制（Single Owner），权责对等闭环** |
| **工作流覆盖** | 场景割裂，无法支撑晨会统筹与团队排期 | 偏研发特化场景，不适配综合性日常团队流转 | **晨会统筹、目标细拆、日常执行、人事交接全流程贯通** |
| **催办督办** | 仅支持个人设备闹钟，无组织节拍感 | 邮件与系统站内信极易被淹没和忽视 | **深度融入钉钉生态，系统规律节拍定时催办，解放肉身催单** |
| **部署与掌控** | 公有云 SaaS 托管，企业数据资产无法自主可控 | 依赖复杂中间件与昂贵商业授权，部署笨重 | **单文件 SQLite 极简自托管，数据资产 100% 掌握在自己手中** |

## 我们的协同理念：打造工作场景全流程

好的工具不仅规范进度，更沉淀组织的交付默契。ToDO 贯穿团队工作从发起到验收的完整生命周期：

1. **坚持单人负责制（Single Owner）**：
   一件任务多人负责往往等于无人负责。ToDO 倡导每一项任务必须有且仅有唯一的直接责任人（Owner），对交付质量端到端闭环；其他跨部门协助人员归入参与人，权责对等不推诿。
2. **任务粒度控制在 1~3 天（WBS 科学拆解）**：
   执行周期超过 1 周的任务极易沦为拖延黑洞。利用 WBS 将庞大战略目标层层化整为零，细化拆解为可独立验收的最小行动单元，让目标看得清、够得着。
3. **系统节拍自驱动（智能定时自动催办）**：
   按团队工作节拍定点汇总团队临期、超期任务，群机器人精准 @责任人。用系统客观的规律节拍驱动全员自我管理，彻底解放管理人员肉身催单的尴尬与内耗。
4. **日常执行 4 维清爽流（兼顾个人深度专注）**：
   基于“分派给我、由我创建、参与协作、关注任务”四维结构清爽收拢待办。员工上班不用在零散的群聊里到处翻找，电脑端大屏统揽、手机端秒级勾选，今日事今日毕。
5. **空间治理与资产零断档（权限隔离与离队交接）**：
   绩效考核、财务等敏感情境开启【仅见相关】，非名下任务物理级隔绝，各司其职；成员调岗或离职移出团队时触发安全拦截，名下任务一键批量平移交接给新指定人，组织数字资产永不流失。

## 技术架构与极简自托管优势

### 前端技术栈 (Client)
- **核心基础**：React 19 + TypeScript 5.9 + Vite 8
- **排版与组件库**：Tailwind CSS 4 + shadcn/Radix UI + Ant Design + Lucide Icons
- **状态流转**：Zustand
- **富文本能力**：TipTap 编辑器引擎

### 后端技术栈 (Server)
- **运行环境**：Node.js + Express 5 (CommonJS 模块规范)
- **数据持久化**：SQLite (`better-sqlite3` 高性能同步驱动)
- **数据库版本控制**：Knex 增量结构迁移 (Migrations)
- **任务调度引擎**：node-cron
- **外部能力集成**：钉钉开放平台 OpenAPI

### 为什么选择自托管架构？
- **数据资产 100% 自主掌控**：任务数据、项目文档、人员架构与内部讨论均存储于本地或企业私有云 SQLite 单文件中，彻底杜绝数据上传到外部第三方云平台的合规与泄露风险。
- **超轻量零依赖**：不需要额外维护 MySQL/PostgreSQL 集群或 Redis 缓存，单端口运行，开箱即用。
- **秒级启动与极低资源占用**：内存占用小，CPU 消耗低，一台极低配置的轻量服务器即可流畅支撑百人规模团队的高频协同。

## 快速上手（本地开发调试）

### 1. 环境准备
- Node.js >= 18.0.0
- npm >= 9.0.0

### 2. 获取代码与依赖安装

```bash
# 克隆代码仓库
git clone https://github.com/Jolly-J/ToDO.git
cd ToDO

# 安装根目录及前后端依赖
npm install
npm --prefix client install
npm --prefix server install
```

### 3. 配置环境变量

从示例模板复制前后端配置：

```bash
# 服务端配置
cp server/.env.example server/.env

# 前端配置
cp client/.env.example client/.env
```

按需修改 `server/.env`（详见文件内部注释）：
- `JWT_SECRET`：设置自定义随机密钥。
- `INITIAL_SUPER_ADMIN_IDS`：设置系统初始管理员用户 ID（以英文逗号分隔）。
- 钉钉参数（如需联调企业免登与机器人功能按需配置）。

### 4. 启动开发服务

```bash
npm run dev
```

服务启动后访问：
- 前端交互界面：`http://localhost:8821`
- 后端 API 服务：`http://localhost:8344`
